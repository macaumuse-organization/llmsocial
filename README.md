# llmsocial

本地运行的多账号社媒收件箱与 AI 回复工作台。集中查看私信与评论，为每个账号配置聊天任务、技能、人设和模型，结合对话上下文起草回复。

它**只回复主动来信的人**：不替你找人、加人、开聊。

## 这个工具不做什么

| 不做 | 挡在哪一层 |
|---|---|
| 自动加好友、关注、搜人、给陌生人发第一条消息 | 出站只有针对已有会话的 `send`，没有加人/关注的能力；会话只能由入站消息或操作者手动创建。「潜在联系人」收的是对方先做过的动作，只读，要人点「开聊」才建对话，开场白永远是待审核草稿 |
| AI 冒充真人建立关系 | 自动发送的首条私信强制带 AI 身份说明，公开回复带署名；模型自称真人会被出站检查拦下 |
| 对方明确要求停止联系后继续发 | 退订永久且跨账号，命中后连「重新生成」都会被拒绝 |
| 把涉及自伤、未成年人、法律纠纷、骚扰的对话交给模型 | 关键词命中直接转人工，**模型根本不被调用** |
| 持续监看屏幕、ADB 操控手机、平台客户端多开登录 | 没有这些代码 |

这些都是代码路径，不是提示词里的一句「请不要」。逐层说明见 [安全边界](docs/安全边界.md)。

## 启动

需要 Node.js 22.18 或更新版本——22.18 起 Node 才默认直接运行 `.ts`，再早的版本会报 `ERR_UNKNOWN_FILE_EXTENSION`。

macOS、Windows、Linux 都能跑。截图识别 macOS 和 Windows 都有（分别需要 Xcode 命令行工具和 OCR 语言包），Linux 没有；非 macOS 的加密主密钥落在 `data/master.key` 而不是钥匙串。

装好 Node.js 之后，一键打开：Windows 双击仓库里的 `一键启动.bat`；macOS / Linux 在终端里 `bash 一键启动.sh`。它会在第一次运行时装依赖、构建界面，起来后自动打开浏览器；已经在运行就只打开浏览器。那个窗口别关，关了服务就停。

手动的话，在仓库目录下：

```bash
npm install
npm run dev
```

打开 <http://127.0.0.1:5173>，首次使用时设置管理密码。正式运行：

```bash
npm run build
npm start
```

正式运行界面位于 <http://127.0.0.1:8787>。

默认仅在本机监听。可将 `.env.example` 复制为 `.env` 配置端口和数据目录，启动时自动读取；已有环境变量优先。这台电脑要开 VPN 才能访问 Google、X、Instagram 的话，到「设置 → 网络代理」打开开关、填代理地址，保存即生效，不用重启——浏览器走系统代理，程序不走，见 [接真号清单](docs/接真号清单.md) 第 2.5 条。账号、对话与配置默认保存在 `data/llmsocial.db`。凭据加密保存，也可引用环境变量或 macOS 钥匙串。

## 平台与接入方式

| 平台 | 当前接入 | 收消息 | 发消息 |
|---|---|---|---|
| 微信个人号 | 聊天桥（Windows）或手动 | 微信里「转发到其他应用」选聊天桥，整段记录进收件箱；或导入聊天截图、文字 | 复制回复，在微信发送后确认 |
| 小红书 | 手动 | 导入聊天截图或文字 | 复制回复，在小红书发送后确认 |
| 抖音 | 手动 | 导入聊天截图或文字 | 复制回复，在抖音发送后确认 |
| 微信公众号 | 平台 API | 回调 | 客服回复 |
| 企业微信客服 | 平台 API | 回调及同步 | 客服回复 |
| X | OAuth / 平台 API | 轮询 | 私信与公开回复，取决于账号权限 |
| Instagram | 平台 API | 回调及轮询 | 私信与评论回复，取决于账号权限 |
| YouTube | OAuth / 平台 API | 轮询评论 | 评论回复 |
| 自建消息桥 | Webhook | 签名回调 | 配置出站地址后可发送 |
| 沙盒 | 本机模拟 | 演练对话 | 仅记录在本机 |

微信个人号、小红书、抖音没有可用的 API，不是功能缺口：抖音的私信 API 已停止新增准入，小红书的只开给有等保和 ICP 资质的技术服务商，微信个人号根本没有。查证过程和出处见 [平台接入](docs/平台接入.md)。

微信个人号在 Windows 上多一条路：**聊天桥**。账号选「微信 + 通用 Webhook」，卡片上点「安装聊天桥」，llmsocial 把它装到这台电脑并注册进微信的「转发到其他应用」菜单；之后微信里多选消息 → 转发 → 转发到其他应用 → 选择电脑中的应用 → 聊天桥，这段记录就进收件箱，AI 起草回复。它只收微信自己导出的文件，不读微信数据库、不碰微信进程，也不替你发消息。源码在 [wechatbridge-win](https://github.com/HeLanGouSheng/wechatbridge-win)。

五个平台 API 连接器均有本地测试，但尚未使用真实凭据验证。添加账号后，需验证授权、消息接收和实际回复；账号列表会提示实际收发的验证状态。平台 API 的接入要求见 [平台接入](docs/平台接入.md)。

### 截图识别：本机、免费、不联网

截图识别用系统自带的能力在本机完成：不花钱、不需要任何 API key、图片不会离开这台电脑，也不会发给任何模型。临时文件 0600 且用完即删。「设置」页可选 `auto / vision / off`，那里也会显示这台机器实际用的是哪个引擎。

| 系统 | 用什么 | 需要准备 |
|---|---|---|
| macOS | Vision 框架 | Xcode 命令行工具（`xcode-select --install`），首次使用时自动编译一个小的 Swift 助手 |
| Windows | 系统自带的 `Windows.Media.Ocr` | 对应语言的 OCR 语言包（设置 → 时间和语言 → 语言和区域 → 中文 → 语言选项 → 光学字符识别）。不用装任何东西，也不联网 |
| Linux | 无 | 导入截图会直接说明原因，改用粘贴文字 |

粘贴聊天文字这条路在所有系统上都能用，不依赖 OCR。

识别出的文字会进入对话记录，参与后续回复生成；那一步用的是你自己配置的模型，与 OCR 无关。

## 日常操作

1. 在「账号」添加账号，选择对应平台与连接方式。
2. 在「模型」配置一个或多个模型，测试连接。支持 Anthropic、OpenAI 兼容接口、Gemini 与本地 Mock。
3. 在「聊天任务」设置目标、成功标准、事实资料、链接、素材库、技能、模型顺序和回复模式。素材库是想让对方去看的东西（短视频、商品页），AI 只在对方的兴趣和素材的「适合」对得上、又有由头时分享一条，发过的不再主动发。
4. 在「收件箱」处理对话。手动账号点「导入截图 / 聊天记录」，可以拖截图（本机识别），也可以把聊天文字整段粘进去——认「名字：内容」和微信电脑版复制出来的「名字 10:23」抬头，解析完再校正文字与发言人，然后起草回复。
5. 审核草稿后发送。手动账号先复制到平台，实际发出后点「我已在平台发送」。复制和保存草稿都不会计为已发送。

继续已有手动对话时，在对话顶部点「补充聊天记录」。账号和联系人自动沿用当前对话；只导入新增内容，避免重复记录。新建导入时，同一账号下相同联系人标识会归入同一段对话，未填标识则新建联系人。

## 回复模式

- **只起草（copilot）**：AI 生成待审核草稿，由操作者决定内容和发送时间。
- **自动回复（autopilot）**：按任务设置和账号发送节奏处理已有对话。首条自动私信包含 AI 身份说明，公开回复包含署名。
- **全局暂停**：继续生成草稿，暂停自动发送。人工确认的发送由操作者控制。

切换为只起草后，尚未发送的自动回复转为待审核。手动结束对话会取消未发送的内容；对方再次发来消息时可重新进入进行中。模型生成期间对话、任务或人工回复发生变化，过时结果不会覆盖当前状态：操作者手动点的生成会提示重新起草，对方来信触发的生成会按最新状态自动重跑一次。

同一账号串行发送，自动消息遵守静默时段和频率上限。连接中断、服务端错误或重启造成发送结果不确定时，需要在平台核对后决定重试，避免重复消息。

## 模型与技能

模型按任务指定顺序尝试；没有指定时，使用全局启用模型的优先级。启用正式模型后，全局后备链不会自动落到离线 Mock。任务明确指定的模型都不可用时，显示失败，不会擅自改用其它模型。每日调用限制包含重试、后备模型和正在进行的请求。

技能以 Markdown 导入、导出和编辑。任务可以组合多个技能。收件箱支持同一段上下文比较多个模型，选中的结果保存为待审核草稿。

首次安装带有离线 Mock，可用「沙盒演练」检查任务与技能的基本流程。使用真实模型的演练会调用相应模型服务并产生其用量；沙盒评分不代表真实用户的接受度或转化率。

## 安全与隐私

- 默认只监听 `127.0.0.1`；webhook 走独立端口，隧道只暴露那个端口。
- 管理密码 scrypt 存储，会话令牌只存哈希，登录失败限流；首次设密码只允许本机。
- 写操作要求自定义请求头并校验 Origin，挡 CSRF；Host 白名单挡 DNS 重绑定。
- 平台凭据 AES-256-GCM 加密，主密钥不在数据库也不在备份里：macOS 存钥匙串，其它系统存 `data/master.key`（权限位 0600 在 Windows 上是摆设，这台机器上有别的账号就要自己用 ACL 管好这个文件）；也可以只存 `keychain:` / `env:` 引用，密钥根本不进数据库，界面只显示引用名。
- 发送先标记 `sending` 再发网络请求；结果不确定时绝不自动重发，宁可漏发。
